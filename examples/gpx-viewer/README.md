# three-map-terrain · GPX viewer

The [live demo](https://whidrubeld.github.io/three-map-terrain/): load a GPX
track and see it on real 3D relief, with an elevation profile, playback,
waypoints and coordinates. A demo track is shown right away; open your own
`.gpx` (it never leaves the browser) or drop it on the page.

React 19, [React Three Fiber](https://r3f.docs.pmnd.rs), [TanStack Store](https://tanstack.com/store),
Tailwind CSS 4, Vite. Fonts: Doto and JetBrains Mono.

## Run

`three-map-terrain` is linked from the repository root, so build the library first:

```bash
# repository root
yarn && yarn build

# this folder
yarn
yarn dev       # http://localhost:5173
yarn test      # GPX parsing, track statistics, terrain fitting
yarn build     # type-check + static build into dist/ (relative paths)
```

Push to `master` deploys `dist/` to GitHub Pages (`.github/workflows/gh-pages.yml`).

## What the library does here

| Feature                         | API                                                    | Where                                                                    |
| ------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| Terrain grid around the track   | `new Map({ source, location, options })`, `map.init()` | [Terrain.tsx](src/scene/Terrain.tsx)                                     |
| Zoom that fits the track        | `Utils.position2tileFraction`, true-scale `zScale`     | [fit.ts](src/lib/fit.ts)                                                 |
| Track draped on the surface     | `map.getTerrainPositionSync`                           | [drape.ts](src/scene/drape.ts)                                           |
| Terrain under the cursor        | `map.pick(raycaster)`                                  | [Probes.tsx](src/scene/Probes.tsx)                                       |
| Grid and walls of the "diorama" | `map.getLocation`, `map.getTerrainPositionSync`        | [Graticule.tsx](src/scene/Graticule.tsx), [Base.tsx](src/scene/Base.tsx) |
| Imagery / wireframe at runtime  | the tiles' own materials, changed in place (no reload) | [Terrain.tsx](src/scene/Terrain.tsx)                                     |
| Elevations for tracks without   | `getTerrainPositionSync(...).z / zScale`               | [World.tsx](src/scene/World.tsx)                                         |

Vertical exaggeration is `scale.z` of the group holding the terrain and
everything on it, so it is free to change. A tile request that stalls does not
hold the intro back: after 25 s the viewer starts with the tiles it has and
refreshes once `map.init()` resolves.

## Code

```
src/
  gpx/        parse.ts (GPX 1.0/1.1 → points, waypoints, metadata), track.ts (stats, sampling)
  lib/        geo math, formatting, terrain fitting
  state/      TanStack stores: settings (persisted), track, terrain, hover, playback, ui
  scene/      R3F scene: terrain, route (Line2), markers, grid, base, camera rig, probes
  ui/         panels, profile, help, overlays, pixel icons — plain elements, no UI kit
  hotkeys.ts  one table for the key handler and the help dialog
```

Every GPX string is untrusted: it is rendered as text, links keep only
`http(s)` URLs.

## Demo tracks

`public/presets/*.gpx` are generated by `yarn presets`
([scripts/make-presets.mjs](scripts/make-presets.mjs)): the route geometry is
the shortest path through the ways of an OpenStreetMap route (Overpass API),
elevations come from the same terrarium tiles the map uses, smoothed like a
barometric altimeter, and the timestamps are **synthesized** (Tobler's hiking
function, a constant-power cycling model) with GPS jitter and rest stops. They
are not real recordings, and their metadata says so.
